# Сводка спецификации после D-051

Статус: DRAFT / NOT APPROVED. Это консолидация существующих решений, не новые требования и не план реализации. DECISIONS.md хранит историю; позднее решение по теме заменяет ранний открытый вопрос. Приоритеты не назначены. Разработка, сетевые изменения, push и запуск исполнителей не разрешены.

## 1. Согласованный продукт
- Независимое приложение Ubuntu с собственными backend и Web UI, первоначально один физический NIC в LAN. OpenWrt остается внешним основным роутером, настраиваемым пользователем вручную; API/LuCI/SSH-интеграции продукта нет.
- Xray — основной кандидат, не одновременная реализация двух движков. Исследовательский snapshot не является выбранным production-релизом.
- VLESS: шесть транспортов, только TLS/REALITY, три варианта flow; перечисленные расширения TLS/REALITY, XHTTP Extra, FinalMask, Mux/XUDP, DNS узла, стратегии IP/Happy Eyeballs, TFO/MPTCP и цепочки (D-009–022).
- SOCKS5/HTTP: без авторизации или username/password; HTTP с TLS и без, полный перечисленный TLS-набор; DNS узла, стратегии IP/Happy Eyeballs, цепочки/интерфейс, TFO/MPTCP (D-043–048). Mux для этих протоколов не утвержден выбором VLESS Mux.
- WireGuard: outbound Xray с одним peer, endpoint, ключи, адреса, MTU, Reserved, Keep Alive и необязательный FinalMask (D-049–050). Не системный WG; импорт .conf исключен (D-051). Общие поля формы PassWall не гарантируют их работу для WG.
- Ручной ввод, импорт и подписки; текст/Base64 URI и Clash/Mihomo YAML только для узлов выбранных протоколов. Без переноса чужих DNS/правил/групп, выполнения команд и загрузки providers/includes по одному факту наличия в YAML (D-024, D-040).

## 2. Общие правила сохранения и применения
- Сохранить и Применить — разные действия. Ни редактирование, ни обновление подписки не изменяют работающую конфигурацию (D-013).
- Семантическая несовместимость допускает невалидный черновик, но блокирует применение. Неверный JSON блокирует сохранение (D-012, D-015).
- Неактивные значения сохраняются для возврата, но исключаются из генерации; свернутая секция сама по себе не делает поля неактивными (D-016).
- Сохраненные и активные зависимости блокируют удаление узла; редактирование черновика не устраняет активную ссылку. Цепочки ограничены согласованным дополнительным слоем, проверяются ссылки/циклы (D-022–023, D-047).
- Неизвестные поля корректного узла сохраняются с невалидным черновиком. Ждать поддержки или исправления источника; без «применить всё равно» и отбрасывания полей ради обхода (D-041–042).
- Секреты защищаются; модель хранения/доступа еще не выбрана. Приватные окружения и конфиги не включаются в Git.

## 3. Подписки — согласованное поведение
- Обновление меняет сохраненные черновики без обязательного preview, источник заменяет ручные правки подписочных параметров с предупреждением. Идентичность/локальные ссылки не заменяются произвольно (D-025–026).
- Исчезнувшие узлы удаляются только без сохраненных и активных зависимостей; остальные помечаются. Это действует лишь для принятого обновления (D-027).
- Ошибка разбора отклоняет обновление целиком. Пустой источник, ноль поддерживаемых узлов или ноль после фильтров — также отклонение без изменения прежних узлов и отметок исчезновения (D-028–032).
- Распознанные неподдерживаемые протоколы пропускаются с отчетом; неизвестный/поврежденный формат не маскируется под такой пропуск. Все режимы фильтров и глобальное наследование сохранены.
- Ручной запуск, после загрузки ОС, ежедневно, по дню недели и интервал 1–24 ч. Автоматические режимы выключены по умолчанию (D-033).
- Auto/Direct/Proxy; явный Proxy при отказе завершается ошибкой без Direct fallback. Это еще не определяет DNS/bootstrap или Auto (D-034–035).
- HTTPS проверяет сертификат/имя по умолчанию; отдельное явное опасное исключение для подписки. HTTP разрешен с предупреждением; HTTPS→HTTP redirect разрешен автоматически с предупреждением постфактум (D-036–038). Это осознанные риски, не гарантия отсутствия утечек.
- Свободный User-Agent и presets; точные строки/default еще не выбраны (D-039).

## 4. Крупные блоки следующего обсуждения
| Порядок | Блок | Что необходимо решить | Что сначала исследовать |
|---|---|---|---|
| 1 | Топология и охват | Какие LAN-клиенты/назначения направляются на Ubuntu; весь или выбранный трафик; собственный трафик Ubuntu | Путь туда/обратно при одном NIC, TCP/UDP, исключения для upstream, петли; сравнение TProxy/REDIRECT/TUN без изменений сети |
| 2 | DNS и IPv6 | DNS клиентов против DNS узлов, допустимость прямых запросов, охват IPv6 | Bootstrap, перехват/обход DNS, IPv6-маршруты и защита от обхода правил; IPv6 endpoint не равен transparent IPv6 |
| 3 | Отказ и применение | При сбое блокировать или разрешать прямой путь; поведение при остановке/перезагрузке; восстановление доступа; границы отката | Проверка кандидата конфигурации, порядок сетевых изменений/перезапуска, активный snapshot, последствия для существующих соединений |
| 4 | Доступ и секреты | Откуда доступна панель, вход/роли, хранение ключей, экспорт/резервные копии | Модель угроз LAN, минимальные привилегии, изоляция сетевого компонента, безопасная диагностика |
| 5 | Эксплуатация и оставшийся scope | Установка/обновления, журналы/статус, нужные правила маршрутизации и прочие разделы PassWall, границы первого релиза | Целевой релиз Xray, совместимость Ubuntu, обоснование стека/хранилища, измеримые критерии производительности |

Порядок — предложение организации обсуждения, не выбранная архитектура. Следующий вопрос должен быть о сценарии сети, а не о выборе пользователем механизма nftables вслепую. Не объединять отказ всего трафика с уже согласованным отказом Proxy-загрузчика подписок.

## 5. Технические пробелы, которые не нужно превращать в повторные вопросы о scope
- Закрепить целевую версию Xray; для каждого поля: тип, default, отсутствие/пустое значение, validator, зависимости, JSON path, пример и критерий проверки.
- Уточнить совместимость transport/security/flow, HTTP/SOCKS credentials и поведение WG; не обещать работу на основании видимости в LuCI.
- Идентификация узлов подписки при переименовании/смене адреса, дубликаты, отсутствующие поля, сохранение локальных ссылок, конкурентные обновления.
- URI/YAML mapping без потери семантики; классификация неизвестных полей; безопасный парсер и лимиты ресурсов.
- Auto/proxy selection, DNS загрузчика, redirects между origin и credentials, timeout/лимиты; расписание: timezone, пропущенные запуски, retry и конкурентность. Требующие продуктового выбора варианты вынести одним связанным блоком после исследования.
- Точный matcher фильтров и нормализация на входе; изменение фильтра при ненулевом результате и политика идентичности.
- Runtime-тесты, сборка и сетевые проверки не выполнялись (NOT_RUN). Статический анализ не доказывает безопасность или работоспособность.

## 6. Найденные устаревшие формулировки и ограничения
Обновлены верхние строки FEATURE_MATRIX (узлы/подписки больше не «не принято»), CONNECTION_GAPS (закрытые вопросы о полях, скрытых значениях и несовместимости), D-001/D-004 и пункты основной спецификации о неизвестных полях/удалении ссылок. Исторические Clarifications сохранены с явным правилом приоритета поздних решений. Неразрешенного противоречия между принятыми решениями при этой документальной сверке не обнаружено; это не полная формальная проверка каждого поля. Ранние PROPOSED и OPEN_QUESTION в исследовательских материалах не отменяют последующие D-решения.

Готовность: набор подключений и основные политики согласованы по частям; полное ТЗ не утверждено. Перед реализацией нужны решения по блокам выше, технические контракты и отдельное утверждение спецификации.

## Уточнение D-052 после консолидации
Охват клиентов выбран: все устройства LAN, их интернет-трафик обрабатывает Ubuntu. В блоке 1 остается выбрать правила direct/proxy и охват собственного трафика Ubuntu; локальные исключения и механизм доставки/возврата требуют исследования. Направление на Ubuntu вручную настраивается на OpenWrt. Это не разрешение сетевых изменений и не выбор proxy-all.

## Уточнение D-053: штатная маршрутизация
Выбран direct по умолчанию и proxy для выбранных назначений. В блоке 1 теперь открыты типы/приоритет правил и собственный трафик Ubuntu, а не базовая политика direct/proxy. Политика отказа прокси остается отдельным нерешенным вопросом; прямой выход при отсутствии совпадения не разрешает обход прокси при сбое.

## Уточнение D-054: способы задания назначений
Согласованы ручные доменные/IP/CIDR-правила и готовые наборы доменов/IP. Требуется исследовать форматы и источники; затем согласовать обновление, приоритет исключений и доменное сопоставление. Конкретные списки пока не выбраны.

## Уточнение D-055: отказ прокси
Для выбранных proxy-назначений утверждена блокировка без прямого обхода при недоступности прокси. Штатный direct-трафик при работоспособной Ubuntu сохраняет прямой путь. Полный отказ Ubuntu, поведение роутера и механизм обеспечения этой гарантии еще открыты; испытания NOT_RUN.

## Уточнение D-056: полный отказ Ubuntu
Выбрано ручное восстановление через роутер с допустимым перерывом доступа. Нужна проверенная инструкция сохранения доступа к управлению и изменения маршрута с явными последствиями для proxy-политики. Автоматическая отказоустойчивость не входит в согласованный сценарий первой версии. Сетевые изменения не выполнялись.
