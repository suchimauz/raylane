# T001 — независимая проверка baseline

Статус: ожидается исследовательский пакет; G1 OPEN. Документ задает критерии, не результаты испытаний.
Base документов: `7ebd9852ef5144f1377f723601abc9ef60e1c66d`.
Связь: T001, FR-001–008/017/019/020/021; US1, предусловия US5.

## Последовательность и владение

1. 05 готовит `packaging/versions.lock`, `docs/engineering/capabilities.md`, `docs/verification/T001-research.md` и сообщает точный commit.
2. 03 независимо проверяет этот неизменный commit; изменения пакета возвращаются 05, архитектурные конфликты — 01/пользователю.
3. 04 независимо воспроизводит безопасные проверки на принятом для проверки commit. Непроведенные проверки — NOT_RUN.
4. 01 сопоставляет evidence и решения; только затем рассматривает закрытие T001 и переход T002/T005. Одного заявления автора недостаточно.

На этапе исследования продуктовый код не изменяется. Этот документ принадлежит 01; он не меняет спецификацию или область разрешенных действий 05.

## Checklist ревью 03

- Exact versions всех выбранных компонентов: Xray, Go, Node, React, SQLite driver, dnsmasq, nftables, iproute2, crypto/parser dependencies. Нет `latest` или неподтвержденных digest.
- Для каждого pin указаны источник, версия/commit, способ получения и проверки, лицензия и существенные ограничения распространения.
- Source baseline, upstream release и проверенный binary artifact разделены. Локальный tag не доказывает upstream provenance или production-ready статус.
- Если checksum вычислен локально, это явно указано; локальный hash сам по себе не является независимым подтверждением подлинности.
- Установленная версия на машине исследователя не подменяет воспроизводимый target baseline Ubuntu 24.04 amd64.
- Проверена согласованность Go toolchain с выбранным Xray source; несовместимость не скрывается сменой scope.
- FR-002–008 покрыты полями, transport/security/flow combinations, зависимостями и статусами supported/unsupported/unverified со ссылками на закрепленные источники.
- Проверены nftset/TPROXY и иные prerequisites; статическое подтверждение capability не выдается за G2 network proof.
- Пробелы доказательств, неподдержанные комбинации и несоответствия требованиям явно блокируют соответствующую часть baseline.
- Нет реальных секретов, приватных источников, данных стенда или неразрешенных внешних действий.

## Уточнения после независимого preflight 03

- Формат lock выбирает 05; минимальное содержание: component/version/commit, точный публичный retrieval URL, дата проверки, лицензия, trust level, evidence status. Для digest указывать алгоритм, значение и происхождение (upstream-published/local). Отсутствующее значение не выдумывать и не считать проверенным.
- Подпись upstream: указать проверенный канал и результат либо NOT_VERIFIED. Утверждение, что канала нет, тоже требует источника.
- Проверить согласованность всех трех документов по pins и source revisions. Расхождение или capability-ссылка на незакрепленный revision — FAIL.
- Исследовательский diff должен содержать только три разрешенных файла, с точным commit/base; посторонние изменения не включать. Чистота общего рабочего дерева не заменяет проверку состава commit.
- Указывать точные Ubuntu package versions для dnsmasq/nftables/iproute2, repository provenance и способ проверки доступности для Ubuntu 24.04 amd64.
- Отдельно отмечать copyleft и ограничения распространения; публичность репозитория не доказывает совместимость всех лицензий.
- Определить supported/unsupported/unverified в matrix; static source support не означает runtime validation. Неисследованные поля явно перечислить.
- Учесть транзитивные зависимости и способ проверки полного замыкания до runnable baseline. Физические go.sum/package-lock создаются T002; требование их наличия в T001 не должно создавать цикл T001 → T002 → T001. T001 фиксирует решения/pins и оставшиеся проверки, T002 не получает автоматического PASS по этим решениям.
- G1 отслеживается раздельно: pins, provenance, capability mapping. Общий gate остается OPEN при недостатке обязательных доказательств любого раздела.


## Независимое evidence 04

Команды определяются по фактическому формату lock и пакету 05, а не выдумываются заранее. Минимум: проверка полноты pins/source/license, воспроизведение разрешенных provenance проверок, сверка capability ссылок с exact source revision, проверка реакции предложенного verifier на несовпадение digest/недоступный artifact, если verifier существует. Отсутствие verifier не является PASS автоматизированного negative test.

Для будущего задания 04 допустимо ограниченное получение необходимых публичных исходников/metadata/artifacts по HTTPS для provenance checks в пределах разрешения пользователя, без запуска загруженного кода. Точный набор и лимиты фиксируются в задании 04. Это не разрешение privileged network tests или изменений сети хоста; запрет загрузок в preflight 03 относился только к тому readonly заданию.

Нельзя запускать непроверенные загруженные scripts/binaries. Никаких sudo, изменения сети/служб хоста, стендовой инфраструктуры, router/SSH, push/deploy. Сетевые и runtime capability tests без доступного разрешенного окружения — NOT_RUN; они не заменяются статическим чтением.

## Формат результата

`taskId`, `status`, `summary`, `artifacts`, `evidence`, `checks`, `risks`, `questions`.
Каждая проверка: `command`, `exitCode`, `executedAt`, `artifactPath`, expected/actual и PASS/FAIL/NOT_RUN. Для NOT_RUN exitCode и executedAt — null, причина обязательна. Отчет привязан к immutable commit и версиям; только redacted evidence.

G1 остается OPEN до проверки результатов. G2–G4 этим пакетом не закрываются. A04 session expiry/retention остается отдельным обязательным контрактным условием до реализации затронутых операций.
