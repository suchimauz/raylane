# Privileged helper contract — design v0

Локальный Unix socket, проверка peer credentials, отдельный user/group; недоступен браузеру или TCP LAN. Не general-purpose shell executor. Envelope: protocolVersion, operationId, expectedGeneration, command, payloadHash. Idempotency по operationId+payloadHash, другой payload с тем же ID отклоняется.

Envelope-детали, зафиксированные в T005 (`contracts/helper.schema.json`, protocolVersion 1): `expectedGeneration` ограничен диапазоном [0, 9007199254740991] (JSON safe-integer range), чтобы любая конформирующая реализация представляла значение точно и сравнение поколений было однозначным; `payloadHash` = SHA-256 поверх канонизированного по RFC 8785 (JCS) объекта payload, payload-only, в UTF-8, в lowercase hex; дубликаты ключей JSON отклоняются на этапе парсинга, до вычисления хеша. Канонизация покрывает только payload, никогда конверт; изменение определения = bump protocolVersion.

Команды: Inspect, ValidateManifest, PrepareGeneration, EngageGuard, ActivateGeneration, VerifyGeneration, RestoreGeneration, StopGuarded, ReleaseProtection, StageArtifact, RegisterReleaseConfirmation. Payload — типизированный manifest из разрешенных объектов: generation ID, listener ports, approved interfaces, canonical destination sets, policy refs, engine/DNS artifacts hashes, и intent-флаг IPv6 TProxy (`ipv6TProxyEnabled`, default false) — флаг фиксирует только намерение, он не доказывает наличие доказанного IPv6-профиля и не является разрешением включать IPv6-перехват. Только helper-owned paths; запрет traversal/symlink escape и arbitrary executable/environment/command text. Xray config компилируется сервером, но helper повторно проверяет профиль и допустимые пути/порты; не доверяет API как root.

## Artefact staging — StageArtifact (D2)
Доставка байт артефакта в helper-owned storage — bounded inline transfer на существующем аутентифицированном Unix socket. Peer credentials проверяются ДО чтения тела запроса. Envelope команды StageArtifact несёт typed artifactKind (engineConfig/dnsConfig/destinationSet/policy), declaredSize, declaredSha256 и contentBase64; никакого peer-supplied file path/name, command или environment. Framing bounded до allocation; decoded size валидируется до materializing large data. Helper генерирует staging identity, recompute SHA-256, валидирует permitted artifact profile и atomically finalises в helper-owned storage. Ни один partial artefact не становится referenceable. Limits: per-object до 1 MiB decoded; per-generation aggregate до 16 MiB; object-count до 64 на generation. Bounded pre-apply staging failures могут удалить собственные partial temporary writes, но не авторизуют retention/secret/history cleanup. Recheck authorization и resource ownership at use; hash alone is not trust. Generated artefacts могут содержать секреты и никогда не логируются и не public-read. Это contract, не authorization запускать privileged helper.

## Release confirmation issuance — RegisterReleaseConfirmation (D6)
Control plane владеет session authentication, CSRF/origin, user confirmation и public issuance. Выпуск подтверждения — closed helper registration operation на существующем peer-authenticated socket, отдельно от ReleaseProtection. Helper генерирует opaque CSPRNG nonce; хранит bounded pending entry с token digest, session identifier (не cookie), target generation, protection-state identity/resource и собственным monotonic expiry (не более 120 секунд). CP возвращает token только авторизованной session; submission revalidates session/CSRF/origin и пересылает matching authorization helper'у. Helper валидирует local binding, expiry и single use и atomically consumes перед release action. Никакой signature scheme или cross-process clock comparison не изобретается. Helper restart инвалидирует все предыдущие pending confirmations явно (fresh boot epoch или эквивалентный empty positive-registration set), даже если active generation не изменился; не утверждать, что restart меняет generation автоматически. Protection-state/generation change также инвалидирует старые confirmations. Auth/session revocation — ответственность CP на каждом issuance/use; helper freshness — собственный token lifetime, не verification CP session TTL. Audit issuance и attempts без values/digests. Same operationId+payloadHash может вернуть prior terminal result, но никогда не reexecute release; fresh operation с consumed token fails. Stop остаётся distinct и guarded.

Helper сам проверяет confirmation, не только его наличие: он проверяет, что confirmation bound к generation, который просят release, и к current protection state, re-verifying binding, freshness и single use против собственного state. Helper доверяет CP authentication и audit для ТОГО, кому принадлежит session, но НЕ его утверждению, что confirmation valid — control plane — authenticated peer, не trusted oracle for release safety.

## Apply protocol
1. Контроллер сохраняет immutable candidate/journal и запускает validation, включая engine config check без применения.
2. Helper закрывает затронутый new-flow gate, сохраняя management/local exclusions; подтверждает durable guard generation.
3. Подготавливает ресурсы поколения; не переписывает активные файлы in-place. Проводит readiness DNS/engine/classification, не только PID check.
4. Переключает kernel batch в пределах атомарности nft transaction; вся операция разных процессов не атомарна. Подтверждает generation после проверки.
5. Контроллер фиксирует active revision только по подтвержденному результату. Crash между подтверждением и DB commit восстанавливается Inspect+journal.
6. Ошибка: вернуть previous generation; при неудаче degraded-guarded. Отсутствие UI/Xray не снимает guard. StopGuarded оставляет защиту. ReleaseProtection требует bound confirmation и audit; повторная операция безопасна.

## Ownership / recovery
Helper управляет только собственными namespace/table/resources, не flush ruleset. Уникальные mark/table allocations проверяются preflight, не копировать 999/255 наугад. Конфликт окружения — ошибка до изменения. nft/system process ошибки не маскируются под success. Persistent recovery manifest содержит hashes/IDs, не открытые секреты; root-owned engine artifacts имеют минимальные права. Recovery при boot восстанавливает gate до разрешения обслуживаемого транзита; конкретный service ordering проверяется изолированно.

## Required negative tests
Недопустимый peer, version mismatch, stale generation, duplicate operation с другим hash, oversized input, path traversal/symlink, неподдержанный interface/port, hostile compiler artifact; остановка API/helper/engine на каждом шаге, full disk и corrupt journal, timeout, rollback failure. Helper crash не доказывает сохранение kernel gate — проверить. IPv6 enable без доказанного профиля отклоняется, не частично применяется.
