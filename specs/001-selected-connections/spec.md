## Область и ценность
Raylane позволяет администратору домашней LAN управлять выбранными внешними подключениями и направлять выбранные интернет-назначения через прокси, оставляя остальные напрямую. Это самостоятельное приложение на отдельной Ubuntu-машине с одним физическим сетевым интерфейсом и собственным Web UI. OpenWrt остается основным роутером, вручную настраиваемым пользователем; приложение им не управляет. PassWall — поведенческий референс, но не образец визуального интерфейса и не автоматическое включение всех его функций.

Основной действующий субъект — администратор настроек; пользователи устройств LAN пользуются сетью без обязательной установки клиента Raylane. Разграничение административных ролей пока не выбрано. Источники подписок и списков — внешние данные, не доверенные команды.

## User Scenarios & Testing
Все результаты проверок NOT_RUN. Сценарии формализуют принятые решения; наличие критериев не означает выполненную приемку. Истории перечислены по потоку работы, не по придуманному приоритету реализации.

### US-01 — Создать и проверить узел
Администратор создает узел выбранного протокола и видит, можно ли его применить.
- Допустимые поля сохраняются без молчаливого изменения семантики.
- Семантически несовместимая конфигурация сохраняется как невалидный черновик, применение запрещено с причиной.
- Синтаксически неверный JSON не заменяет сохраненное значение.
- Выключение опции сохраняет ее поля для возврата, но они не влияют на применяемую конфигурацию. Сворачивание секции не выключает опцию.
- Секретные ключи скрыты по умолчанию; ошибка не раскрывает значения секретов.
**Независимая проверка**: синтетические узлы каждого выбранного протокола, допустимые и недопустимые комбинации.

### US-02 — Отделить сохранение от работающего состояния
- Сохранение, импорт и обновление подписки не меняют работающую конфигурацию.
- Применение требует отдельного явного действия и допускается только для проверяемого допустимого состояния.
- Узел с сохраненной или активной зависимостью нельзя удалить; интерфейс показывает зависимости. Удаление ссылки только из черновика не снимает активную зависимость.
- Цикл или неверная ссылка цепочки блокирует применение.
**Независимая проверка**: сравнение сохраненного и активного состояния до/после операций; бесшовность и автоматический откат не обещаны.

### US-03 — Обновить подписку без потери контроля
- Успешное обновление автоматически меняет сохраненные подписочные параметры, включая ручные правки; редактор предупреждает заранее. Работающее состояние остается прежним.
- Исчезнувший узел без зависимостей удаляется; используемый остается с отметкой и объяснением.
- Поврежденная запись отклоняет все обновление без частичных изменений. Корректный пустой источник, ноль поддерживаемых узлов и ноль после фильтрации также не меняют прежний список или отметки исчезновения.
- Распознанный неподдерживаемый протокол пропускается с отчетом. Неизвестный формат не маскируется под такой пропуск.
- Корректный узел выбранного протокола с неизвестными полями сохраняется невалидным; поля не теряются. Применение возможно лишь после поддержки/исправления источника и повторной проверки, без «применить всё равно».
**Независимая проверка**: синтетические источники с изменением, исчезновением, пустым ответом, ошибкой и неизвестным полем.

### US-04 — Управлять загрузкой подписки
- Автоматические способы запуска выключены по умолчанию; доступны ручной, после загрузки ОС, ежедневный, по дню недели и интервал 1–24 часа.
- В явном Proxy недоступность прокси дает ошибку без прямого запроса.
- HTTPS проверяет сертификат/имя по умолчанию; исключение включается явно для конкретной подписки и сопровождается предупреждением, не включается после ошибки автоматически.
- HTTP допускается с предупреждением без отдельного разрешения. HTTPS→HTTP переход разрешен автоматически; downgrade отражается в результате, включая последующую ошибку.
- Выбранный Proxy сохраняется на перенаправлениях. Исключение HTTPS-проверки подписки не распространяется на узлы.
**Независимая проверка**: контролируемый источник/прокси, включая сертификат и redirect; реальные секреты не используются.

### US-05 — Направлять LAN-трафик по правилам
- Целевой охват — интернет-трафик всех устройств LAN через Ubuntu при корректной ручной настройке внешнего роутера.
- Назначения, выбранные правилами, идут через прокси; остальные — напрямую. Поддерживаются ручные домены/IP/CIDR и готовые наборы доменов/IP.
- При недоступном прокси выбранные для него соединения не выпускаются напрямую. Штатный direct-трафик при работоспособной Ubuntu должен сохранять путь.
- При полном отключении Ubuntu допустим перерыв доступа и ручное восстановление через роутер с объяснением последствий обхода для защиты proxy-направлений.
- Обычные исходящие соединения ОС/приложений Ubuntu не перехватываются. Служебные запросы Raylane не смешиваются с этой категорией.
**Независимая проверка**: будущий отдельно разрешенный стенд с проверкой прямого/прокси пути, отсутствия петель и отказов. Клиентский IPv6 и доменная классификация проверяются по FR-020.

## Requirements

### Подключения
- **FR-001**: VLESS, SOCKS5, HTTP-прокси и WireGuard — выбранные типы внешних узлов. SOCKS4/4a и локальный публичный proxy-server не включены этим выбором (D-007, D-043).
- **FR-002**: VLESS сохраняет raw/mkcp/ws/grpc/httpupgrade/xhttp, TLS или REALITY и flow: пустой/xtls-rprx-vision/xtls-rprx-vision-udp443. Наличие опций не обещает допустимость всех комбинаций (D-009–012).
- **FR-003**: VLESS имеет XHTTP Extra, FinalMask, ALPN, uTLS/fingerprint, chain SHA256 pin, проверяемое имя, PEM проверки, cipher suites, ECH, REALITY ML-DSA-65, Mux и concurrency/XUDP concurrency. Дополнительные возможности не включаются автоматически (D-014–018).
- **FR-004**: VLESS/SOCKS5/HTTP имеют DNS имени самого узла Auto/TCP/UDP/DoH; стратегии Auto, предпочтение IPv4/IPv6, только IPv4/IPv6 и Happy Eyeballs. При включенном Happy Eyeballs ручная стратегия неактивна. Это не политика DNS сайтов LAN (D-019–020, D-046).
- **FR-005**: VLESS/SOCKS5/HTTP имеют TFO/MPTCP, выключенные по умолчанию; без автоматической настройки ядра, интерфейсов и маршрутов (D-021, D-048).
- **FR-006**: VLESS/SOCKS5/HTTP имеют альтернативные режимы цепочки: выключено, предварительный узел, конечный узел, выходной интерфейс; один дополнительный слой, проверка ссылок/циклов. Произвольная длина и прямой обход при сбое не включены (D-022–023, D-047).
- **FR-007**: SOCKS5/HTTP поддерживают отсутствие авторизации и username/password. HTTP поддерживает обычное соединение и TLS с SNI, ALPN, uTLS/fingerprint, chain SHA256 pin, именем сертификата, PEM, cipher suites, ECH. REALITY для HTTP не утвержден (D-043–045).
- **FR-008**: WireGuard — один peer внутри выбранного движка: endpoint, public/private keys, необязательный pre-shared key, локальные адреса, MTU, Reserved, Keep Alive и FinalMask JSON, выключенный по умолчанию. Не системный WireGuard; без импорта обычного .conf (D-049–051).

### Состояния и зависимости
- **FR-009**: сохранять/применять отдельно; семантическая невалидность блокирует применение, неверный JSON — сохранение. Неактивные значения хранить без использования. Не исправлять настройки молча (D-012–016).
- **FR-010**: защищать сохраненные и активные ссылки от удаления; показывать зависимости и причины ошибок. Не обещать бесшовность или откат без отдельного контракта (D-023).

### Подписки и импорт
- **FR-011**: ручной ввод, импорт и подписки; текст/Base64 URI, Clash/Mihomo YAML только для выбранных узлов. Не переносить автоматически rules/DNS/groups и не выполнять содержимое (D-024, D-040).
- **FR-012**: обновление сохраненных параметров, исчезновение, частичные ошибки и пустые результаты обрабатываются строго по US-03. Локальная идентичность/ссылки не заменяются произвольно (D-025–030, D-032).
- **FR-013**: фильтры: выключено, discard, keep, оба режима приоритета, глобальное наследование; неизвестные поля — по US-03 (D-031, D-041–042).
- **FR-014**: все перечисленные способы запуска; Auto/Direct/Proxy; свободный User-Agent и presets. Auto не обозначается как гарантированно проксированный путь до определения контракта (D-033–035, D-039).
- **FR-015**: HTTP, HTTPS, исключения проверки и downgrade — по US-04; без переноса опасного исключения на другие подписки/узлы (D-036–038).

### LAN и границы продукта
- **FR-016**: охват LAN, direct-default, ручные/готовые правила, отказ и восстановление — по US-05 (D-052–057).
- **FR-017**: самостоятельные backend/Web UI; без OpenWrt API/LuCI/SSH и автоматической настройки роутера. Xray — основной кандидат, не утвержденная production-версия. Второй движок сейчас не реализуется (Constitution).
- **FR-018**: интерфейс следует согласованным принципам Apple Design, с ясным различием сохраненного/активного/невалидного состояния, доступностью и reduced motion; не копирует LuCI. Конкретные темы не утверждены.
- **FR-019**: секреты маскируются и не попадают в журналы/публичные артефакты; неизвестные импортные значения считаются потенциально секретными. Конкретная модель хранения/входа остается OQ-02.

- **FR-020 (D-058)**: отдельный IPv6 TProxy выключен по умолчанию; фильтр IPv6 proxy-доменов независим. При выключенном IPv6-перехвате защита IPv6 не обещается. Управляемый DNS направляет direct-домены через direct DNS, proxy-домены через proxy DNS; распознавание произвольного DoH/скрытого имени не гарантируется. При неготовой классификации блокировать новые соединения затронутых клиентов. После локальных/служебных исключений приоритет block → explicit direct → proxy → default direct, пересечения показывать при проверке. Штатная остановка сохраняет защиту proxy-направлений; снять ее можно отдельным явным действием с предупреждением. Доступ к управлению исключен из перехвата.
- **Приемка FR-020**: проверить оба состояния IPv6-перехвата и независимость DNS-фильтра, конфликт всех видов правил, неготовую классификацию, штатную остановку и явное снятие защиты. Новые соединения затронутых клиентов при неготовой классификации не выходят напрямую; после остановки proxy-направления не получают прямой обход, управление остается доступным. До явного снятия защиты предупреждение сообщает последствия. Runtime NOT_RUN; механизм и DNS-серверы определяются в plan.

### Key Entities — концептуально, не схема хранения
- **Узел**: тип, параметры, источник происхождения, сохраненное состояние, валидность и зависимости.
- **Подписка**: источник, настройки загрузки/фильтра/расписания, связанный набор узлов, результат последнего обновления.
- **Правило назначения / набор правил**: условия выбора, назначенный путь, происхождение; порядок и обновление требуют OQ-01/OQ-03.
- **Активное состояние**: примененные значения и ссылки, отдельно от редактируемых.
- **Отчет проверки/обновления**: результат, безопасные причины, версия проверяющего компонента, NOT_RUN/PASS/FAIL там, где проверка действительно выполнялась.

## Edge Cases
- Невалидный JSON против корректного, но несовместимого узла; неизвестное поле против неизвестного формата или неподдерживаемого протокола.
- Скрытое неактивное значение против свернутой активной секции.
- Исчезнувший узел с активной ссылкой; переименование/дубликаты; источник не вернул поле после ручного изменения.
- Пустой keep-фильтр; пустой источник; все записи неподдерживаемые; одна поврежденная запись среди корректных.
- HTTPS ошибка, downgrade, отказ Proxy, перенаправление на другой origin с credentials.
- Пароль без имени; пустой пароль; IPv6 endpoint, Reserved неправильной длины, MTU/Keep Alive вне контракта.
- Кэш DNS, shared IP/CDN, literal IP, клиентский DoH, неизвестное имя назначения и bootstrap-петля.
- Пустые списки при старте, ошибка выбора маршрута, отсутствующий узел, отказ upstream, смерть процесса и отключение Ubuntu — не одна и та же ошибка.

## Success Criteria
Критерии документальной приемки требований, а не заявления о реализации:
- **SC-001**: для каждого поля выбранного набора имеется проверяемый контракт; неподтвержденные комбинации не объявляются поддержанными. Покрытие — 100% утвержденного набора, техническая трассировка ведется отдельно.
- **SC-002**: во всех сценариях сохранения/импорта/обновления без «Применить» активное состояние не меняется.
- **SC-003**: каждый отклоненный результат подписки оставляет прежние узлы и их отметки без изменений; каждый пропуск распознанного неподдерживаемого протокола отражен в отчете без секретов.
- **SC-004**: ни один узел с сохраненной/активной зависимостью не удаляется; каждая проверяемая несовместимость дает причину и блокирует применение.
- **SC-005**: во всех согласованных сценариях отказа Proxy-загрузчика/выбранного proxy-направления нет автоматического прямого запроса. Область наблюдения и матрица сетевых отказов уточняются до испытаний.
- **SC-006**: тестовые секреты не появляются в диагностике и публичных артефактах; приватные/PSK-ключи скрыты по умолчанию.
- **SC-007**: инструкция ручного восстановления описывает доступ к управлению, действия и последствия для proxy-политики; ее работоспособность проверяется отдельно перед приемкой сети.
Порог пропускной способности, число клиентов/узлов и время восстановления не заданы пользователем; численные обещания не выдумываются.

## Не входит в согласованный scope
Программное управление роутером; реализация второго движка; системный WireGuard и .conf; автоматический импорт чужих YAML rules/DNS/groups или выполнение команд; произвольная длина цепочек. Другие разделы PassWall, балансировка и автоматический failover не включены самим фактом наличия в референсе. Ни реализация, ни сетевые изменения, ни push не разрешены этой спецификацией.
